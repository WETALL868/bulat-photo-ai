## 2. Индексация: замечания и что делать

### 🔴 И-1. Цена и наличие в разметке устарели — 2 999 карточек из 3 636

**Что происходит.** Готовые страницы собраны 27 сентября (`lastmod` в карте —
`2026-09-27` у всех адресов). Цены и остатки обновляются каждый день и живут в
`live/catalog-live.json`, который подтягивает браузер. Статическая страница —
та, что видит робот, — осталась с сентябрьскими цифрами.

**Пример** (`/product/bumaga-hi-black-hb-php-gl-10h15-230-100`):

| | значение |
|---|---|
| цена в `<script type="application/ld+json">` | **410 ₽** |
| видимая цена в статическом HTML | **410 ₽** |
| фактическая цена сейчас | **306 ₽** |

**Масштаб:** цена расходится на **2 999 карточках (82 %)**, наличие — на **220**.

**Чем это плохо.**
* В выдаче Яндекса и Google показывается цена, которой нет. Покупатель приходит
  и видит другую — это прямой удар по доверию и по конверсии.
* Google и Яндекс сверяют микроразметку с тем, что видно на странице. Их робот
  умеет выполнять JavaScript: он догружает `live/catalog-live.json`, получает
  306 ₽ и сравнивает с разметкой, где 410 ₽. Расхождение цены — нарушение правил
  расширенных сниппетов, карточка товара может потерять цену и наличие в выдаче.
* Если магазин пойдёт в Яндекс.Маркет или Google Merchant Center, такие позиции
  отклоняются автоматически.

**Решение.** Пересобирать готовые страницы вместе с обновлением цен, а не раз в
неделю. Обновление каталога уже ходит по расписанию — добавить в тот же
сценарий шаг пересборки:

```bash
npm run catalog && npm run seo
```

Если полная пересборка 16 029 страниц каждый день тяжела (около трёх минут и
600 МБ), есть два более лёгких пути:

* пересобирать только карточки товаров, у которых изменилась цена или наличие;
* либо вынести цену и наличие из статической страницы в отдельный маленький
  фрагмент, который подставляется на сервере при выдаче. Тогда разметка и
  видимый текст всегда берутся из одного живого источника.

**Проверка после исправления:** у случайных 20 карточек цена в `ld+json`, цена в
видимом HTML и цена в `live/catalog-live.json` совпадают.

### 🔴 И-2. Сайт не подтверждён в Яндекс.Вебмастере и Google Search Console

В разметке нет ни `yandex-verification`, ни `google-site-verification`,
подтверждающих файлов в корне тоже нет.

**Чем это плохо.** Без подтверждения нельзя:
отправить карту сайта на обход, увидеть ошибки индексации и страницы, выпавшие
из поиска, переобходить изменённые адреса, задать регион магазина (для Яндекса
это прямо влияет на позиции по коммерческим запросам), отслеживать запросы.

**Решение.**
1. Яндекс.Вебмастер → добавить сайт → подтвердить мета-тегом, положить в `<head>`
   шаблона `index.html` и пересобрать страницы.
2. Google Search Console → ресурс с префиксом URL → подтвердить тем же способом.
3. После подтверждения: отправить `sitemap.xml` в обоих; в Вебмастере задать
   регион «Москва» и проверить раздел «Диагностика».

### 🔴 И-3. На сайте нет ни одного счётчика

Ни Яндекс.Метрики, ни Google Analytics. Магазин запускается вслепую: не будет
видно ни откуда приходят люди, ни где они уходят из оформления заказа.

Для Яндекса у Метрики есть побочная польза: она помогает роботу находить
страницы, на которые мало внутренних ссылок, — а у этого сайта такие есть (И-6).

**Решение.** Поставить Яндекс.Метрику с включённым вебвизором и целями
«добавил в корзину», «оформил заказ», «купил в 1 клик». Google Analytics 4 — по
желанию. Счётчик ставится в шаблон, страницы пересобираются.

⚠️ При настройке целей не передавать в счётчик телефон, e-mail и адрес
покупателя — только факт события и сумму.

### 🟡 И-6. 765 товаров не достижимы по ссылкам без JavaScript

В статическом HTML категории видно **12 товаров**; ссылок на вторую страницу
нет — пагинация работает только скриптом. По всем категориям и страницам

**Решение** (любое одно):
* добавить в HTML категории обычные ссылки на страницы пагинации
  (`/catalog/laser?page=2`), пусть даже визуально скрытые в блоке «ещё»;
* либо сделать для каждой категории страницы `/catalog/laser/2`, `/3` с
  собственным `canonical` на себя;
* либо завести раздел-карту «Все товары» со ссылками, разбитый по буквам или
  категориям.

### 🟢 И-8. Служебные параметры адреса для Яндекса

Каталог использует `?page=`, `?sort=`, `?f=`, `?tab=`. Сейчас сервер на любой

добавив в `robots.txt`:

```
Clean-param: sort&page&f&tab&v&acc&pp
```

Не обязательно, но экономит краулинговый бюджет на каталоге из 3 636 товаров.

## 4. Безопасность: замечания и что делать

### 🔴 Б-1. Нет заголовка HSTS

Переадресация с `http` на `https` есть, но без `Strict-Transport-Security`
первый заход по `http://` всё равно уходит открытым — этого достаточно для
перехвата на публичном Wi-Fi.

**Решение.** В `.htaccess`, в блок `<IfModule mod_headers.c>`:

```apache
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
```

Ставить **после** того, как убедились, что весь сайт и поддомены работают по
https: откатить такой заголовок у уже зашедших посетителей нельзя до истечения
срока. Сначала поставьте `max-age=300`, проверьте неделю, потом поднимите до года.

---

### 🔴 Б-2. Нет защиты от помещения сайта в чужой фрейм

Ни `X-Frame-Options`, ни `Content-Security-Policy: frame-ancestors`. Чужой сайт
может открыть ваш в прозрачном фрейме поверх своей страницы и собирать нажатия —
для страницы оформления заказа и для админки это реальный риск.

**Решение:**

```apache
Header always set Content-Security-Policy "frame-ancestors 'self'"
Header always set X-Frame-Options "SAMEORIGIN"
```

---

### 🔴 Б-3. Приём заказов без ограничения частоты и без защиты от повторов

Это замечание перешло из аудита 2 октября и на момент снимка **не исправлено**.
Проверено на изолированном стенде: двенадцать заказов подряд приняты, одна
корзина с одним ключом создала три разных заказа.

**Чем это плохо.** Бот за минуту забьёт папку заказов, таблицу и почту
менеджера. При включённой онлайн-оплате повторная отправка — это два платежа и
разбирательство с покупателем.

**Решение.** Вынести ограничитель, который уже написан для подписки на наличие,
в общую функцию и применить ко всем POST: заказ — 10 в час на адрес, расчёт
СДЭК — 60, отзыв и обратный звонок — 5. Плюс ключ идемпотентности: браузер
кладёт в заказ случайный идентификатор, сервер хранит соответствие «ключ →
номер» и при повторе возвращает тот же номер, ничего не создавая.

### 🟡 Б-4. Листинг каталогов не запрещён явно

В `.htaccess` нет `Options -Indexes`. Если на сервере включён показ содержимого
папок, по адресам `/assets/img/vtt-full/`, `/live/`, `/data/`, `/ops/` будет
виден список файлов.

**Решение:** первой строкой `.htaccess`:

```apache
Options -Indexes
```

Проверить: `curl -s https://hiblack-msk.ru/assets/img/vtt-full/ | head`.

### 🟡 Б-5. Папка `ops/` отдаётся наружу

`/ops/hiblack-vtt/mapping.json` — 122 КБ соответствий «код магазина → код
поставщика» на 3 636 товаров. Не секрет, но внутренние данные, показывать их
незачем.

**Решение.** Добавить `ops` в список запрещённых папок `.htaccess` (строка 35) и

---

### 🟡 Б-6. Новые файлы `api/` не внесены в запрет

Запрет перечисляет только `admin`, `reviews-store`, `config-path`,
`shop.config.sample`. Появившиеся `auth.php`, `cdek.php`, `db.php`,
`order-store.php`, `yookassa.php` защищены только проверкой внутри кода. Она
работает, пока PHP исполняется; при сбое обработчика исходники с логикой оплаты
отдались бы текстом.

**Решение.** Расширить список:

```apache
<FilesMatch "^(admin|auth|cdek|db|order-store|yookassa|reviews-store|config-path|shop\.config\.sample)\.php$">
  Require all denied
</FilesMatch>
```

### 🟢 Б-7. Нет `Permissions-Policy`

Сайту не нужны камера, микрофон и геолокация — стоит сказать это явно:

```apache
Header always set Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()"
```

## 5. Что нужно проверить уже на сервере

Снимок не отвечает на вопросы о том, как сервер ведёт себя в реальности.
Эти команды выполняются с любого компьютера, ничего не меняют:

```bash
# 1. Заголовки главной: есть ли HSTS, CSP, X-Frame-Options; какой сервер
curl -sI https://hiblack-msk.ru/ | sed -n '1p;/^[Ss]erver/p;/^[Ss]trict/p;/^[Cc]ontent-Security/p;/^[Xx]-Frame/p;/^[Xx]-Robots/p'

# 2. Переадресации
curl -sI http://hiblack-msk.ru/ | head -2
curl -sI https://www.hiblack-msk.ru/ | head -2
curl -sI https://hiblack-msk.ru/catalog/ | head -2

# 3. Служебные разделы закрыты от индексации
for u in /cart /checkout /search /admin /api/status; do
  echo -n "$u -> "; curl -sI "https://hiblack-msk.ru$u" | grep -i x-robots | head -1
done

# 4. Служебные файлы недоступны
for u in /ops/hiblack-vtt/mapping.json /api/yookassa.php /api/db.php /db/schema.sql /tools/ /var/orders/; do
  echo -n "$u -> "; curl -s -o /dev/null -w "%{http_code}\n" "https://hiblack-msk.ru$u"
done

# 5. Листинг каталогов
curl -s https://hiblack-msk.ru/assets/img/vtt-full/ | head -5

# 6. Сжатие
```
