# Импорт каталога VTT

Конвейер: SOAP-выгрузка → нормализация → обогащение → стор → витрина.

Контракт взят из официального WSDL (`http://api.vtt.ru:8048/Portal.svc?singleWsdl`,
HTTP 200, 47 119 байт), а не из предположений:

| Что | Значение |
| --- | --- |
| Target namespace | `http://portal.vtt.ru` |
| Namespace данных | `http://portal.vtt.ru/data` |
| Endpoint | `http://api.vtt.ru:8048/Portal.svc` |
| SOAPAction | `http://portal.vtt.ru/IPortalService/<Метод>` |

Раньше здесь стоял `tempuri.org` — типовое значение для WCF. С ним сервис
не ответил бы вообще.

## Операции

Все двенадцать методов WSDL реализованы. В полной выгрузке участвуют:

| Операция | Роль в конвейере |
| --- | --- |
| `GetItemPortion` | Основная выгрузка каталога порциями |
| `GetCategories` | Дерево категорий: `Id`, `Name`, `ParentId` |
| `GetCategoryItems` | Официальное членство товара в категории — перекрывает раскладку по тексту `Group`/`RootGroup` |
| `GetGoodsCompatibilityInformation` | `ItemId`, `ModelBrand`, `ModelCategoryName`, `ModelName` — модели принтеров полями, а не строкой |
| `GetAdditionalAttributes` | `CategoryId`, `ItemId`, `IntValue`, `StringValue` — хранятся как есть |
| `GetRelatedItems` | Идентификаторы связанных товаров |
| `GetRuntimeItemsPortion` | Отдельный частый синк: `Price`, `AvailableQuantity`, `TransitQuantity`, `MainOfficeQuantity` |

Остальные (`GetItems`, `GetRuntimeItems`, `GetItem`, `GetRuntimeItem`,
`GetCategoryRuntimeItems`) доступны в клиенте и проверяются диагностикой.

Недоступность любой из смежных операций не роняет выгрузку: каталог уже в
сторе, а причина отказа уходит в отчёт.

## Обогащение и хэш карточки

Хэш отвечает на один вопрос: изменились ли данные **поставщика**. Поэтому в
него не входит ни одно поле, которое мы вычислили сами, —
`categoryId`, `categorySource`, `compatibilityLabels`,
`compatibilityDetailed`, `attributes`, `related`, — а также отметки
времени и оперативные цены с остатками.

Без этого правила повторная выгрузка объявляла бы изменившимся весь
каталог: обогащение дописывает поля уже после того, как карточка легла в
стор. Проверено тестом «обогащение не делает повторную выгрузку
изменением всего каталога».

Три источника не перезаписывают друг друга и лежат рядом:

| Поле | Откуда |
| --- | --- |
| `groupId` | `GroupId` из `ItemDto` — как прислал поставщик |
| `categoryId` | Раздел, который выбрали мы; `categorySource` говорит, чем |
| `compatibilityText` | Строка `Compatibility` из `ItemDto` — как есть, без разбора |
| `compatibilityLabels` | `GetGoodsCompatibilityInformation` — единственный источник списка моделей |

Сборка сайта в сеть не ходит. Синхронизация — отдельная команда, она
наполняет `vtt-data/`, а `npm run build` собирает каталог из уже готовых
данных. Поэтому сборку можно повторить в любой момент и получить тот же
результат, а падение VTT не ломает деплой.

## Два источника одних и тех же данных

SOAP-клиент готов и покрыт тестами, но egress к `api.vtt.ru` из облачной
среды закрыт политикой организации (HTTP 403 на CONNECT). Полная реальная
выгрузка при этом уже есть — её сделали учётной записью владельца и отдали
файлом. Поэтому импорт из CSV входит в **тот же** путь:

```
сырой ряд → normalize → categories → store → publish → витрина
```

Всё, что гарантирует SOAP-ветка, работает и здесь, потому что это тот же
код: идемпотентность, сохранность сырых строк, отчёт о раскладке, запрет
физического удаления.

| Что | Откуда | Команда |
| --- | --- | --- |
| Реальный каталог, 9 483 позиции | `VTT_full.csv` (37 колонок = весь ItemDto) | `npm run vtt:csv -- vtt-source/VTT_full.csv` |
| То же по сети | `GetItemPortion` и смежные операции | `npm run vtt:full` |
| Фикстуры для тестов | `vtt/fixtures/` | `npm run vtt:mock` |

Стор фикстур (`vtt-data-mock/`) и стор реальных данных (`vtt-data/`) —
**разные каталоги**. Раньше `--mock` писал в `vtt-data/` и одним запуском
затирал бы настоящую выгрузку синтетикой; смешать их теперь нельзя.

## Что реальные данные исправили в предположениях

Контракт был написан по WSDL, но смысл полей виден только на данных. Три
находки изменили код:

| Поле | Что предполагалось | Что на самом деле |
| --- | --- | --- |
| `Vendor` | артикул товара | **марка техники** (HP, Kyocera-Mita, Canon — 33 значения). Артикул лежит в `NameAlias` |
| `Price` | цена в рублях | цена в валюте поставщика. Рублёвая — только `PriceLocal`; отношение по 8 511 позициям 84,273–84,333 |
| `Price` = −1 | цена | **цены нет** — так помечены 972 позиции. Витрина показывает «Цена по запросу» и не продаёт кнопкой |
| `Compatibility` | список моделей | свободный текст: рядом лежат «LJ 3052/3055», «Повреждённая упаковка» и «с чипом». Список моделей даёт только `GetGoodsCompatibilityInformation` |
| `PhotoUrl` = `dummy.jpg` | адрес картинки | **нет картинки** — 3 282 позиции |

Отдельно: в `ItemRuntimeDto` полей всего пять и `PriceLocal` среди них нет.
Положить оперативный `Price` в рублёвую цену значило бы уронить ценник в
восемьдесят четыре раза, поэтому оперативная цена переводится в рубли по
курсу **самой этой позиции**, снятому с полной выгрузки.

## Команды

```bash
# Проверка связи, учётных данных и контракта. Одна короткая порция.
npm run vtt:diagnose

# Полная выгрузка каталога в vtt-data/
npm run vtt:full

# Цены и остатки (можно часто, каталог не трогает)
npm run vtt:runtime

# Весь конвейер на фикстурах: без сети и без учётных данных
npm run vtt:mock

# Каталог сайта из стора
npm run catalog:vtt

# Preview: настоящий каталог + 24 импортированных товара с пометкой ДЕМО
npm run build:preview

# Тесты конвейера
npm test
```

Полезные флаги `vtt/bin/vtt-sync.mjs`:

| Флаг | Что делает |
| --- | --- |
| `--mock` | Фикстуры вместо сети |
| `--store=<путь>` | Другой каталог стора (по умолчанию `vtt-data/`) |
| `--config=<файл>` | Другая конфигурация (по умолчанию `vtt/config.json`) |
| `--portion=<N>` | Размер порции (по умолчанию 500) |
| `--allow-insecure-http` | Осознанно разрешить http-endpoint |
| `--no-categories` | В моке: проверить поведение без `GetCategories` |

### Связанные товары

`GetRelatedItems` — поштучная операция: один вызов на карточку. На каталоге
в десятки тысяч строк безлимитный обход означал бы десятки тысяч запросов к
чужому сервису за один синк, поэтому у неё есть предел и параллельность:

```json
{ "relatedItems": { "enabled": true, "limit": 0, "concurrency": 4 } }
```

`limit: 0` — без предела. Отчёт всегда говорит, скольких обошли из скольких
(`requested` / `ofTotal` / `limited`), чтобы «связей нет» нельзя было
спутать с «до них не дошли». Отказ по правам выясняется одной пробой, а не
повторяется на каждом товаре.

## Секреты

Только переменные окружения. В файлы конфигурации они не пишутся — сборщик
конфигурации отвергает файл, в котором нашёлся `login` или `password`.

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `VTT_LOGIN` | да | Логин VTT |
| `VTT_PASSWORD` | да | Пароль VTT |
| `VTT_SERVICE_URL` | нет | Переопределить адрес сервиса |

Пароль вырезается из логов и отчётов по значению, а не по имени поля: он
может попасть в середину SOAP-ответа или в текст ошибки. Проверено тестом.

## HTTP-endpoint

Официальный адрес опубликован как `http://api.vtt.ru:8048/Portal.svc` — без
TLS и на нестандартном порту. По такому каналу логин и пароль идут открытым
текстом. Поэтому реальный запуск по `http://` требует явного
`--allow-insecure-http`, а предупреждение печатается всегда.

**Перед запуском в облаке** нужно либо получить от VTT https-endpoint, либо
выполнять синхронизацию из доверенной сети.

## Что лежит в vtt-data/

```
vtt-data/
  items/<шард>.json     нормализованные товары, ключ — Id из VTT
  raw/items/*.json      сырые порции ItemDto, дедуплицированы по хэшу
  raw/categories/*.json сырой ответ GetCategories
  raw/compatibility/*   сырой ответ GetGoodsCompatibilityInformation
  raw/attributes/*      сырой ответ GetAdditionalAttributes
  raw/runtime/*.json    сырые оперативные порции
  state.json            курсор возобновления, дерево категорий, отметки времени
  reports/              отчёты последних синхронизаций
  .sync.lock            блокировка параллельного запуска
```

Товары не удаляются. Пропавший из выгрузки помечается `active: false` — и
только после синхронизации, дошедшей до конца.

## Ручные правки

`catalog-source/vtt-editorial.json` — правки, которые синк не затирает:

```json
{
  "VTT-00042": {
    "name": "Своё название для витрины",
    "description": "Редакционный текст"
  }
}
```

Ключ — `Id` товара в VTT. Текст поставщика, собранный из фактов текст и
редакционный текст хранятся раздельно и не перезаписывают друг друга.

## Фильтр публикации

`vtt/config.json`, поле `publishFilter`. Сужает витрину, но не стор: полный
набор всегда выгружается целиком, фильтр решает только что показывать.

```json
{
  "publishFilter": {
    "brands": ["Hi-Black"],
    "excludeBrands": [],
    "categories": []
  }
}
```

## Demo-отзывы в preview

VTT отзывов не отдаёт, и придумывать их нельзя. Поэтому у импортированных
товаров в preview стоят демонстрационные записи — их видно и их
невозможно принять за отзыв покупателя:

* до трёх записей на товар, собранных **только** из фактических полей
  выгрузки этого товара (артикул, ресурс, совместимость, остатки, раздел
  поставщика) — ни одного придуманного утверждения;
* оценка 5 из 5 стоит у самой записи и подписана «демо-оценка, в рейтинг
  товара не идёт»;
* `rate` и `reviews` у товара остаются нулями;
* страница помечена `noindex,nofollow`, исключена из `sitemap.xml`, а
  `aggregateRating` и `Review` в микроразметку не попадают.

Отзывы на уже существующих товарах магазина не тронуты.

## Картинки

Отдельный этап, `npm run vtt:images`. Исходные адреса не подменяются: в
сторе остаётся ровно то, что прислал поставщик, а соответствие «адрес →
локальные файлы» живёт манифестом `vtt-data/images/manifest.json`.

* загрузка с ограниченной параллельностью, таймаутом и кэшем — повторный
  запуск ничего не перекачивает;
* WebP и AVIF, ширины 320/640/960, `srcset` собирается из настоящих
  размеров файлов;
* **ничего не растягивается**: исходник уже 320 px даёт единственный
  вариант в свою ширину, а не замыленную картинку в 960;
* неудачи запоминаются вместе с причиной, чтобы сборка не билась в один и
  тот же отсутствующий файл.

```bash
npm run vtt:images                        # всё, чего ещё нет
npm run vtt:images -- --limit=200         # первые 200
npm run vtt:images -- --from-dir=./photos # без сети, из папки
npm run vtt:images -- --report            # только счёт
```

Сейчас манифест пуст: `b2b.vtt.ru` закрыт той же политикой egress, что и
`api.vtt.ru`. Карточки без картинки показывают заглушку «Фото не
передано» — это честнее, чем ссылка на недоступный http-адрес.


## Раскладка по разделам витрины

Таблицей, а не регулярками: `vtt/src/shop-taxonomy.mjs`. Пятнадцать
корневых разделов поставщика разложены по десяти разделам витрины явно, а
всё, чего в таблице нет, уходит в «Прочее» **и называет себя в отчёте**.
Раньше раздел угадывался по тексту названия, и на реальном ассортименте
фотобумага, отвёртки и принтеры оказались бы среди лазерных картриджей —
причём заметить это было бы нечем.

| Раздел витрины | Позиций |
| --- | --- |
| ЗИП и запчасти | 4 379 |
| Картриджи лазерные | 3 079 |
| Тонеры | 691 |
| Картриджи струйные | 570 |
| Чернила | 362 |
| Бумага и плёнки | 251 |
| Обслуживание и инструмент | 81 |
| Печатающая техника | 37 |
| Матричные картриджи | 28 |
| Прочее | 5 |

Марка техники берётся из `Vendor` таблицей соответствий, а не поиском
подстроки: подстрока «Konica» нашлась бы и в «Konica Minolta», и в
«Minolta», разведя один бренд по двум разделам.

## Превью на тысячах товаров

`npm run artifact` собирает набор файлов, а не один HTML. На 9 579 товарах
каталог весит около 24 МБ, и файл со встроенными данными просто не
публикуется. Но главное не размер: витрина умеет грузить каталог по
частям — чанк деталей открывается только при открытии карточки, — а
встраивание отменяет это умение и заставляет браузер проглотить весь
каталог до первого экрана.

Индекс при этом сжимается (`tools/index-pack.mjs`): словари для
повторяющихся колонок, общий префикс адресов картинок, слаг не хранится,
когда совпадает с идентификатором. 2 520 КБ → 1 869 КБ, и разбор
восстанавливает строку байт в байт — проверено тестом на круговой обход.
